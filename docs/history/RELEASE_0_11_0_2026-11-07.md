# Release 0.11.0: agent call counts and answer receipts — 7 November 2026

**VergeCommon 0.11.0 went live on vergecommon.com on 7 November 2026 at 18:12:16 UTC**, on the owner's decision. It adds two things for agents on top of what production already ran (`5d1a276`):

- **Call counts.** The MCP handler counts requests per day and per tool and serves them at `GET /mcp/stats` (counts only, no request content, 90 days, stored in `mcp-stats.json` under `/data`). `VERGE_MCP_STATS=0` turns counting and the endpoint off; it is unset in production.
- **Answer receipts.** Every public tool answer carries a `source` object (name, URL, license, version, a link to check or start a co-op) and a second text line starting `Source: VergeCommon`. The two discovery tools moved their old top-level `source` string into that object as `retrieved_from`.

Nothing else from main shipped. Environment values and secrets are not recorded here.

- Staging, before the switch: the exact image on an empty data directory with no network, no host ports and no secrets, with `VERGE_WOODLAND_DFM=1`. `/healthz` reported `ca4b9fc` and 0.11.0; anonymous `tools/list` returned the five public tools; woodland projects were open.
- After the switch, from outside the server: `/healthz` ok at `ca4b9fc`, 0.11.0; anonymous `initialize` 200; anonymous `tools/list` exactly the five public tools; `Authorization: Bearer not-a-real-token` returns 401; anonymous `example_pooling_draft` returns the `source` object (VergeCommon, https://vergecommon.com, AGPL-3.0-only, 0.11.0, link to `/coop/`) and the `Source: VergeCommon` line; `GET /mcp/stats` 200 with `persisted: true` and that day's row counting the checks; `/woodland/` 200 and open.
- `tests/woodland_acceptance.py` passed 7/7 against production and deleted its test accounts.

## Rollback

On the server: `/root/v0110-rollback.sh` (the same as `bash /root/v0110.sh rollback 20261107T180818Z`). It stops the new container and restores `vergecommon-pre-v0110-20261107T180818Z`, which runs `5d1a276` with woodland projects on.

## Known gaps for the next release

- The MCP `initialize` handshake still reports `serverInfo` version `0.1.0`, hard-coded in `mcp/server.mjs` and not tied to the release version.
- Requests refused with 401 (an invalid token) are rejected before the MCP handler and are not counted in `/mcp/stats`.
